# Ghost hunt game module

A cooperative ghost hunting game played on Counter-Strike: Source's maps: investigators
search a map for the room a ghost haunts, using equipment that picks up what the ghost
does. This is the first step: one piece of equipment (the EMF reader), rooms, a nav mesh
with a simple ghost AI that walks it, and the ghost throwing things around. For now the
ghost is always visible, so its behaviour can be watched while it is being built.

```
ose_viewer --game ".../Counter-Strike Source/cstrike" --map cs_office --exec "ghosthunt 1"
```

`ghosthunt 1` must be set before the map loads (`--exec` does that). Without it the module
does nothing, so normal CS:S play is unchanged. Players spawn in the `investigator` team
(no weapons, CT player models) at the map's CT or T spawns.

## How it works

- **Rooms** (`src/rooms.cpp`). Where they come from, by `gh_rooms_source` (default `auto`,
  the first that gives any):
  1. a rooms file `content/scripts/ghosthunt/rooms/<map>.txt` (see `devroom.txt` for the
     format: named rooms made of boxes);
  2. the places of the map's nav file (`maps/<map>.nav`, which every CS:S map ships):
     each place ("Bathroom", "StorageRoom", "MainHall" on cs_office) is a room made of the
     boxes of its areas, from their floor to about a storey above;
  3. guesses from the map's soundscapes: each `env_soundscape(_proxy)` gives a box from the
     walls around it (rays from it, the median per side so doors do not count, limited by
     its radius), a `trigger_soundscape` its brush. A room is named after a sound source
     target inside it ("Bathrooms", "Sodamachine"), else after the soundscape. Rough, but
     it works on maps without a nav file.
- **Nav mesh** (`src/navmesh.cpp`): the map's nav areas and their connections (read by
  the engine's `assets/nav.h`). Maps without a nav file get a grid generated by walking a
  player sized box from the spawn points (32 unit cells, steps up to 18, drops up to 64).
  Paths are A* over the areas, through the edges they share.
- **Ghost** (`src/ghost.cpp`): picks a favourite room (not a spawn room if it can help it),
  stands still a few seconds, walks to a random spot in its room, and sometimes
  (`gh_roam_chance`) roams to somewhere else nearby and then returns. Every 8-20 s it
  throws a physics prop within 220 units that it can see (away from itself, a bit upwards,
  spinning); when nothing is in reach it tries again 2 s later. Every 12-30 s it touches
  something. It is drawn with a CS:S player model, pale and see-through.
- **EMF** (`src/emf.cpp`): what the ghost does leaves a trace for 20 s: 2 for a touch,
  3 for a throw (the trace moves with the prop). A ghost with EMF 5 evidence
  (`gh_ghost_emf5`, random by default) makes 35 % of its throws read 5. The reader at the
  bottom right of the screen shows the strongest trace within 100 units: 1 (nothing) to 5.

## Console

| Command / cvar | |
| --- | --- |
| `ghosthunt 1` | play the hunt on the next map |
| `gh_status` | nav mesh, rooms, where the ghost is and what it does |
| `gh_rooms` | the rooms with their boxes, nav areas and bounds |
| `gh_rooms_guess` | the rooms the soundscapes suggest |
| `gh_rooms_reload [auto\|file\|nav\|soundscape]` | use rooms from another source |
| `gh_rooms_save [current\|nav\|soundscape] [file]` | write rooms to a file (default `<map>_rooms.txt`) to edit and put at `content/scripts/ghosthunt/rooms/<map>.txt` |
| `gh_ghost_room [name]` | show the ghost's room, or move it (`sv_cheats 1`) |
| `gh_ghost_throw` | make the ghost throw now (`sv_cheats 1`) |
| `gh_seed <n>` | the same hunt every time (0: random) |
| `gh_ghost_visible`, `gh_ghost_alpha`, `gh_ghost_model` | how the ghost is shown |
| `gh_ghost_speed`, `gh_roam_chance`, `gh_throw_min/max/range/speed/maxmass`, `gh_touch_min/max` | its behaviour |
| `gh_emf_range`, `gh_emf_duration`, `gh_emf5_chance`, `gh_hud_emf` | the EMF reader and traces |

Debug views (they also work in `ose_render --exec`):

| cvar | Shows |
| --- | --- |
| `gh_debug_rooms 1` / `2` | each room's bounds, name (the ghost's in red) and the floor of its boxes / every box; the room you are in |
| `gh_debug_nav 1` / `2` | nav areas near the view coloured by room, links (one-way ones red, half length), the area under you / plus area ids and places |
| `gh_debug_ghost 1` | the ghost's box, state, rooms, evidence, timers, last event, and the path it walks |
| `gh_debug_throws 1` | each throw for 30 s: from the ghost to the prop, the direction, the prop's flight, a label; the throw range; a console line per throw attempt |
| `gh_debug_emf 1` | every EMF trace with level, cause and time left; the reader's range |
| `gh_debug_range` | how far the nav and room views reach |

`ent_info` / `ent_dump` describe the ghost's state too (it is the entity `ghost`, class
`gh_ghost`).

## Not yet

The ghost is never hidden and has no hunts, types or other evidence; there is no other
equipment. The hunt runs on the server's world: in a networked game clients see the ghost
and the props it throws, but not the EMF reader or the debug views. Room boxes from nav
places stop about 100 units above the floor of each area.
